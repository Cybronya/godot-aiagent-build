    错误格式 `<配置文件>: <字段路径>: <说明>`，stage ∈ {config_load, config_validate}。

  `SurvivalArena`（holdout，`Levels/survival_arena.json` 驱动；拾取物/陷阱/奖励机关/

  Python `level_planner.validate_level` 与 GDScript 运行时校验为同规则集的两个镜像实现。
- 踩坑记录（重要，易再犯）：
  1. 新增 `class_name` 脚本后必须先 `godot --headless --path . --import` 注册全局类，
     否则报 "Could not find type"。
  2. 敌人 `target_path` 必须**入树后**用 `enemy.get_path_to(player)` 计算；
     用 `entities.get_path_to(player)` 会少一层 `..`，追击目标解析为空（敌不动）。
  3. holdout 首生成时间规则：`delay > 0` → 延迟到达即生成第一波、随后每 interval 一个；
     `delay = 0` → 首个也在 interval 后（分别复现精英/原敌人生成节奏）。
  4. 场景改配置驱动后，依赖导出参数的既有测试需显式 `level_config_path = ""`
     走遗留通道（test_survival_arena 阶段 F、test_elite_enemy 阶段 G）。
  5. 既有测试会调用适配层私有入口（`arena._finish(true)`），重构时需保留兼容委托。
